# 4.9.4 — Service Navigation Scroll UX Hotfix

Version 4.9.4 replaces the competing scroll animations from 4.9.3 while keeping the 4.9.1–4.9.2 dynamic tab/editor model unchanged.

## Live-site issue reproduced conceptually

On a page with many generated tabs, a long tab click can pass several sections before reaching its destination. In 4.9.3 every intermediate section was allowed to become active during the browser smooth-scroll, and every active change could launch another horizontal smooth-scroll. The result was a tab strip that chased the vertical animation.

## Runtime rules

- Clicking a tab locks the active state to the requested destination until that navigation finishes.
- Vertical movement uses the browser's native compositor smooth scrolling rather than a custom frame-by-frame animation.
- Intermediate sections do not flash active while a click-scroll passes them.
- User wheel, touch or navigation-key input cancels programmatic movement immediately and returns control to normal scrollspy.
- Final placement receives one instant sub-pixel/sticky-offset correction after scrolling settles.
- `html { scroll-behavior: smooth }` can no longer accidentally animate a correction that is intended to be instant.

## Manual scrolling

The active-section reading line is placed inside the usable viewport below the sticky Service Navigation instead of directly on its bottom edge. This allows the tab state to follow the section a person is actually reading rather than waiting until the next section heading has already reached the sticky bar.

At the bottom of the document, the last available navigation section is explicitly selected.

## Many-tab horizontal behaviour

- Tabs remain one line with horizontal overflow.
- The strip moves the minimum distance necessary to reveal the active tab instead of re-centering the row on every change.
- During manual vertical scrolling, horizontal reveal waits briefly for scroll idle, preventing competing animations.
- CTA buttons remain outside the horizontal strip at the approved breakpoint.

## Accessibility and motion

- `aria-current="location"` remains synchronized with the active tab.
- `prefers-reduced-motion: reduce` uses instant vertical and horizontal movement.
- URL hashes and browser history remain usable for deep links.
