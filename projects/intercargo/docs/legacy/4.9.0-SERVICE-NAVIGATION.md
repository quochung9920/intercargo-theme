# 4.9.0 — Dynamic Service Secondary Navigation

> **Superseded editor UX:** 4.9.1 keeps this dynamic data model but adds a central live tab manager with drag order, title override, visibility and fixed target ID controls. See `4.9.1-SERVICE-NAVIGATION-MANAGER.md`.

## Authority and purpose

`intercargo/service-navigation` is the Gutenberg placement/control point for the service-page secondary navigation. It is **not** the source of the tab list.

Authority remains:

1. the current Intercargo theme for `.container`, global gutters, typography, colours and section architecture;
2. the supplied Air Freight HTML for `.air-secnav` geometry, sticky behaviour, overflow and the 1280px CTA breakpoint;
3. the actual top-level section order on the current WordPress page for tab content.

## Dynamic tab contract

Tabs are generated from the page's top-level Intercargo sections that occur **after** the Service Navigation block.

For each eligible section:

1. the target comes from the section's real DOM anchor;
2. the default label comes from the section's own first visible heading;
3. an editor may set **Sub-navigation title** on that section to override only the tab label;
4. an editor may disable **Show in Service Navigation** on that section;
5. reorder/delete/add the section and the navigation updates automatically. There is no second manually maintained list.

Duplicate section anchors use the same `-2`, `-3`, ... suffix sequence as the frontend section renderer, so the generated target remains correct when a section type appears more than once.

Synced body sections are resolved from their current `wp_block` content on the frontend. The editor preview also resolves loaded synced-pattern records when available.

## Not reusable / not syncable

The Service Navigation block is deliberately `syncable: false` and `supports.reusable: false`.

Its tab content belongs to the current page structure and therefore must never be saved as a shared section. Sharing it would snapshot page-specific navigation and recreate the duplication/staleness problem this release removes.

Other body sections retain their normal local/shared behaviour. Their optional navigation metadata travels with the section itself, which is the correct ownership boundary.

## Editable content

Only the two CTA labels belong to the Service Navigation block and remain editable inline:

- primary: `Talk to our team`
- secondary: `Get the guide`

CTA destinations are configured in the block inspector. The tab list itself is read-only because it is derived data.

Every eligible body section receives a small **Service navigation** inspector panel:

- **Show in Service Navigation**
- **Sub-navigation title** (optional; blank = use section heading)

## Responsive behaviour

- existing global `.container`; no secondary max-width or page-gutter system;
- horizontal scrolling for the dynamic tab row where needed;
- scrollbar visually hidden;
- CTAs hidden below 1280px, matching the Air Freight source;
- sticky frontend behaviour with WordPress admin-bar offset;
- non-sticky editor behaviour;
- IntersectionObserver updates active state and `aria-current="location"`.
