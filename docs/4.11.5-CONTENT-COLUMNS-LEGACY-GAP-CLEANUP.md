# 4.11.5 — Content Columns legacy gap cleanup

## Root cause

Pre-4.11.3 saved `core/group` markup could still contain the global `section-head-gap` class. `global.css` loaded after the section stylesheet and re-applied `display:flex` plus `gap: var(--section-gap)`, so the visual gap remained even though new templates stopped serializing the class. The legacy PHP fallback also still emitted the class.

## Fix

- Remove `section-head-gap` from the legacy PHP renderer.
- Use `.content-columns .content-columns-layout` with `display:block` and `gap:0` so already-saved markup renders correctly immediately.
- When the block is opened in Gutenberg, remove `section-head-gap` from the saved content group and persist the clean class list on the next save.
- Extend contracts so this cannot regress while only checking the new template.
