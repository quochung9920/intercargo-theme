# 4.11.2 — Content Columns cleanup

## Decision

`Service Criteria` and `Service Criterion` were duplicate content models and are removed completely as block packages.

The canonical model is now:

- **Content Columns** (`intercargo/reasons`) — top-level section
- **Content Column** (`intercargo/content-column`) — repeatable item inside Content Columns

## Editor behavior

Content Columns owns the section heading, optional introduction and Theme selector.

Columns are native repeatable items. Editors can add, duplicate, delete and reorder them without changing section code. The child item lives in the separate **Intercargo — Section Items** category and is scoped to Content Columns through its `ancestor` contract.

Themes:

- Homepage
- Service — Paper
- Service — White

The layout uses responsive `auto-fit` columns, so additional items wrap cleanly instead of forcing a fixed three-column grid.

## Removal migration

A one-time 4.11.2 migration converts already-saved `intercargo/service-criteria` / `intercargo/service-criterion` markup into Content Columns / Content Column markup and applies the `service-paper` theme. The obsolete package directory and block registrations do not remain in the theme.

Pre-4.11.2 attribute-based `intercargo/reasons` instances are hydrated into native Content Column children only when they have no saved child tree. Existing child content is never rebuilt.
