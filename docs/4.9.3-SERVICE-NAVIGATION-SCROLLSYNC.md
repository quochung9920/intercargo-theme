# 4.9.3 — Service Navigation Scroll Sync

Version 4.9.3 completes the many-tab runtime behaviour without changing the dynamic editor/data model introduced in 4.9.1–4.9.2.

## Many-tab display

- The tab strip remains a single horizontal row and never compresses labels.
- When the tab list exceeds the available width it scrolls horizontally while CTA actions remain outside the scrolling strip.
- Whenever the active section changes, its tab is automatically brought into the visible portion of the strip. If it is outside the viewport, it is centred inside the tab strip.
- Manual touch/trackpad horizontal scrolling remains available.

## Precise section tracking

The old centre-screen `IntersectionObserver` heuristic has been replaced with a deterministic reading-line calculation.

The reading line is immediately below the sticky Service Navigation. The active tab is always the last target section whose top has crossed that line. This works consistently for:

- short sections,
- tall sections,
- repeated section types,
- reordered navigation tabs,
- fast wheel/trackpad scrolling,
- browser resizing.

Tab order can differ from page section order; active-state calculation follows document section order, while the visual tab list continues to use the editor-defined `tabOrder`.

## Precise anchor scrolling

Clicking a tab no longer relies on native hash scrolling. The runtime calculates the sticky nav height and its sticky top offset, then positions the target section immediately below the navigation so the heading is not covered.

The same correction is applied when:

- opening a page with a matching URL hash,
- using browser hash navigation,
- clicking a Service Navigation tab.

The URL hash is still updated for deep-linking and browser history.

## Motion

Smooth scrolling is used normally. `prefers-reduced-motion: reduce` switches all automatic scrolling to instant movement.
