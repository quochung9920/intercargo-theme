# 4.9.1 — Dynamic Service Navigation Manager

> **Superseded editor UI:** 4.9.2 keeps the same dynamic data model but collapses each managed tab to one inline row and removes Target ID from this manager. See `4.9.2-SERVICE-NAVIGATION-COMPACT-MANAGER.md`.

## Purpose

The Service Navigation remains page-local and derived from the actual top-level sections below it. Version 4.9.1 adds an editor-facing manager without creating a second manual navigation data model.

## Live manager

Selecting `intercargo/service-navigation` opens **Tabs (N)** in the block inspector. The list updates from the unsaved Gutenberg block tree in real time.

Each discovered section row provides:

- a drag handle to change **tab presentation order** without moving the page section;
- a **Show** checkbox;
- **Tab title**, which is an optional override. Blank continues following the section heading live;
- **Target ID**, which is optional. Blank keeps the section's automatic theme anchor.

The actual metadata continues to live on the source section. Service Navigation stores only `tabOrder`, an array of stable section keys. This keeps add/remove/duplicate operations dynamic while allowing page-specific tab order.

## Unlimited/repeated sections

Every eligible local section instance receives a stable `serviceNavKey` the first time it is managed. Gutenberg duplication can copy the old key, so the editor detects collisions and assigns a new key to the duplicated instance.

Target IDs have two modes:

1. **Automatic**: theme default anchor plus the existing unique suffix contract, for example `#services`, `#services-2`, `#services-3`.
2. **Fixed**: editor supplies `sectionAnchor`, for example `#pricing`. Duplicate fixed IDs are still uniquified safely (`#pricing-2`) rather than emitting invalid duplicate DOM IDs.

Composition-backed and custom-rendered sections now use the same optional `sectionAnchor` contract. Defaults remain unchanged when no fixed ID is supplied.

## Reusability boundary

`intercargo/service-navigation` remains:

- `syncable: false`
- `supports.reusable: false`

It is dynamic page state and must not be promoted to a shared section. Body sections retain their existing reuse/sync behavior.

## Service Hero hover hotfix

Only the Service Hero starter field's pointer-hover state is aligned to the site's existing light form-field treatment:

- border becomes `#aaa79f`;
- background remains unchanged;
- no hover box-shadow is introduced.

Normal, focus, invalid, validation and submit-button states are unchanged.
