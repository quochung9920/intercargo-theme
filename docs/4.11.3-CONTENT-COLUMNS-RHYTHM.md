# 4.11.3 — Content Columns rhythm hotfix

## Problem

Two service-page Content Columns instances could look like different components: the white preset used a larger column-title size, and the wrapper still carried the global `section-head-gap` utility even though Content Columns also added its own explicit margins. WordPress core/group flow margins could therefore compound the intended spacing. An empty optional intro also made the vertical rhythm harder to reason about.

## Resolution

- Both service presets use the same typography metrics.
- The service preset distinction is visual only: `Service — Paper` changes the surface and uses the dark rule; `Service — White` uses white with the light rule.
- The Content Columns wrapper owns all direct-child vertical margins and neutralizes WordPress flow-layout margins locally.
- The columns use the global `--section-gap` after the final header element (intro when present, H2 when not).
- The redundant `section-head-gap` class is no longer serialized by new Content Columns instances. Existing saved markup that still contains the class is safe because the scoped direct-child rhythm overrides it.
- Generic `.three-cols` and `.reason-card` selectors are scoped under `.content-columns` to avoid cross-section CSS coupling.
